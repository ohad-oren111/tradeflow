## Q1 — Persist `pnl_epoch` (durable drawdown baseline)

- **What:** The drawdown brake measures realized loss since `pnl_epoch`, which reset to process-start on every boot. #170 rolls the contract by restarting, so each auto-roll (~4×/yr) + every redeploy silently zeroed the baseline. Made the epoch durable: boot order = env override > restore persisted value > create+persist once. Read-then-write-once (a valid stored epoch is never overwritten on a routine restart).
- **Why:** Last hardening hole; the armed brake (#169) is not fully trustworthy until the baseline survives restarts.
- **Mechanism / design decision:** v30 §13 preferred Supabase, but there is **no key-value/settings table** and **DDL cannot be applied autonomously** from the VPS (no Postgres creds; PostgREST can't run `CREATE TABLE`; `kill_switch_state` returns 404). The app container has **no host-mounted volume**, so an in-container file dies on `--force-recreate`. Chose a **Docker named volume** (`tradeflow-state` → `/var/lib/tradeflow`, env `KILL_SWITCH_STATE_DIR`): survives `up -d --force-recreate`/`build`/roll-restart, needs zero operator migration, and fits the brief's exact 3-file scope (docker-compose.yml carries the volume). Deviation from the Supabase backend is documented in the PR.
- **Files (exactly 3):** `src/execution/kill_switch.py`, `docker-compose.yml`, `tests/test_kill_switch.py`. Protected-file diff (`src/instruments/`, reconciler, router, strategy) empty.
- **Tests:** added 6 cases (restore-not-overwrite; create+persist-once then restore; env override wins+persists; restored epoch drives drawdown with trip value unchanged; unwritable dir → graceful non-persisted fallback; corrupt file → treated as absent). `pytest tests/test_kill_switch.py` 52 passed; full suite **948 passed** (10 pre-existing warnings). black+ruff clean.
